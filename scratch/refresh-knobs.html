The refresh knobs of open claude
in chrome.

When you change a file in this repo, you usually have to re-load something before the change is visible. Different files require different re-loads. This is the map.

codemode branch · ref dcc8cc7 · seven knobs, one stack

01the seven knobs

# knob how what it resets
K1 hard-reload the page Cmd+Shift+R · or ?v=N browser cache for that tab's assets
K2 reload the extension chrome://extensions → reload service worker code, in-memory SW state; cascades to respawn native-host.js
K3 restart the browser quit all windows, reopen re-reads native messaging manifests; resets per-browser state
K4 re-run install.sh ./install.sh <ext-id> writes a fresh native messaging manifest into the OS dir
K5 kill MCP processes pkill -9 -f "…" terminates the MCP server process and its wrangler/workerd children
K6 reconnect MCP /mcp · or send any message claude code re-launches the killed MCP server from disk
K7 npm install (cd host && npm install) refreshes node_modules after a dep change

K5 and K6 always go together. Killing without reconnecting just leaves things off; reconnecting without first killing just talks to the stale process.

Every file in this repo ends up affecting one of five live components. Read the diagram top-down: a code change at the top of a row enters the system here, and the corresponding knob on the right is what makes that component re-read its source.

08nuclear reset

When the system is misbehaving and you can't tell which knob to turn:

# 1. kill everything we own
pkill -9 -f "server-codemode\|server-hybrid\|mcp-server.js\|wrangler dev\|wrangler-dist/cli\|workerd"

# 2. (optional) clean the wrangler state dirs
rm -rf host/codemode/worker/.wrangler /tmp/oc-wrangler-*

# 3. reinstall deps in case anything is half-installed
(cd host && npm install) && (cd host/codemode/worker && npm install)

Then in the browser:

  • chrome://extensions → toggle the OCIC extension off, then on (forces a full SW recycle)
  • close every browser window and reopen
  • in claude code: /mcp and reconnect each variant

This sequence is K7 K5 K2 K3 K6 in one go. Use sparingly — usually one of the targeted recipes above is enough.

09why each knob exists

Short mental model so you can predict the right knob next time:

browser tab cache

The browser caches HTML/CSS/JS aggressively. K1 covers all static asset changes you serve.

mv3 service worker lifecycle

The service worker is a separate JS runtime initialized by Chrome from background.js and content.js on extension load. Once loaded, the SW keeps running (subject to Chrome's eviction lifecycle) and never re-reads its source. K2 is the only way to re-evaluate extension code.

native messaging manifest

A JSON file in an OS-specific directory that Chrome reads at browser startup. K3 is the only way to make Chrome see a changed manifest; K4 is what writes a new one.

mcp server processes

Spawned by claude code on first use (or on /mcp reconnect) from the files on disk. They never reload their own source. K5 forces termination; K6 forces re-launch.

wrangler dev as a child process

It's a child of the MCP server process, spawned with detached:true in its own group. We never need to kill wrangler separately — killing the MCP parent group-signals it dead. That's why all the codemode/hybrid rows above are K5 K6 without a separate wrangler entry.

native-host.js spawn cycle

Launched by Chrome on demand when the extension calls chrome.runtime.connectNative(). When the extension reloads, the port disconnects, the old native-host.js exits, and the next reconnect respawns it with the new code. K2 implicitly refreshes native-host.js too — the cascade arrow in the diagram.
